If you’re on this page, it probably means you’re wondering: **what is Game Telemetry in GOMI?**  

---

GOMI is a remapping tool, but it’s also a tool for learning code by playing games.   

**Telemetry** is information you receive from a target object, such as a game, drone, piece of software, robot, or device.   
  
You can receive telemetry through a network connection, such as **UDP or WebSocket**, or you can simply collect information manually by writing it down or entering it yourself.   

Because **GDScript is moddable**, you can add code that reads telemetry and connects actions to that information.   

That’s where things start getting interesting.   

Instead of simply creating a macro that repeats predefined actions, you can start creating something closer to a **bot**, where your code reacts to what is happening in the game.   

And that is also where you cross a very important line.   

As soon as your code starts reading game state and automatically reacting to it, your game account may become bannable. For most games, this is no longer just a harmless macro. You’ve moved into botting or automation territory.   

Macros are already pretty close to the ban line.    

**Telemetry-driven automation crosses it.**     

But, honestly, that’s also where learning to code through games starts becoming much more interesting.      

And then there’s the next step: **making money from it.**    

That’s where things can move from *“probably against the game's rules”* to *“possibly against the law.”*    

So... don’t.     

---

The point of all this is simple:   
**GOMI provides a Game Telemetry input so you can connect game information to code and use it as a way to learn programming through games.**    

The goal is not to help you cheat.   
The goal is to make learning code fun.
